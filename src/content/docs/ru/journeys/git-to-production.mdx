# Из Git в production

Доставка из Git доступна, если это разрешено текущим тарифным планом.

## Основной сценарий

1. Настройте интеграцию GitLab, GitHub, generic Git или External SSH в разделе **Settings > Integrations**.
2. Зарегистрируйте выделенный Build Worker и проверьте его возможности.
3. Создайте или откройте Container, Deployment, Compose Project или Pages Project.
4. Выберите режим Repository и укажите репозиторий, ветку, build context и Dockerfile или Compose-файл.
5. Добавьте Build Secrets, ограниченные источником. Они передаются как secret mounts BuildKit, а не как обычные аргументы сборки.
6. Поставьте сборку в очередь и проверьте разрешение источника, назначение worker, логи, результаты поиска уязвимостей и итог политики.
7. Разворачивайте только одобренный неизменяемый digest.
8. Проверьте состояние и commit развёрнутой версии.

## Поведение Compose

Сборка Compose из репозитория может создать отдельную дочернюю сборку для каждого service. Rollout продолжается только после одобрения каждого ожидаемого артефакта. Ошибочная, отклонённая, отменённая или вытесненная дочерняя сборка блокирует публикацию ревизии.

## Проверки безопасности

- Фиксируйте развёртывание по digest, а не по изменяемому tag.
- Принимайте автоматическую сборку и автоматическое развёртывание как отдельные решения.
- Не размещайте учётные данные в URL репозитория, аргументах сборки или логах.
- Считайте хост Build Worker одноразовым и изолированным.
- До зависимости от автоматической доставки без оператора подтвердите поведение при понижении плана или утрате права по тарифному плану.
