Этот сценарий создаёт публичное HTTPS-приложение из образа для Container или источника Git.

## 1. Подготовьте вычислительные ресурсы

Зарегистрируйте Docker Node и Node nginx. Убедитесь, что оба находятся в сети и имеют необходимые порты, хранилище и возможности runtime.

## 2. Создайте рабочую нагрузку

Для простого сервиса выберите автономный Container, для проверяемого по состоянию сине-зелёного rollout и отката — Deployment, а для многосервисного приложения — Compose Project. Настройте image, command, environment, secrets, порты, restart policy, ограничения и управляемые volumes.

## 3. Настройте проверку состояния

Выберите опубликованный HTTP Route для проверки состояния рабочей нагрузки. Настройте path, ожидаемый диапазон статусов, необязательное совпадение с телом ответа, timeout, interval и порог медленного ответа. Не публикуйте трафик, пока состояние не станет стабильным.

## 4. Зарегистрируйте домен и TLS

Добавьте Domain, разместите его на Node nginx, настройте DNS и выпустите или загрузите сертификат.

## 5. Создайте Route

Выберите управляемую рабочую нагрузку как upstream. Используйте Secure Link, если не хотите обычный опубликованный путь управления. Включайте WebSockets или пользовательское поведение пересылки только когда это нужно приложению.

![Здоровый Ingress Route, направляющий трафик к рабочей нагрузке Docker через Secure Link](/screenshots/product-tour/ingress-route.png)

## 6. Проверьте результат

- публичные DNS и TLS;
- состояние приложения и логи;
- access/error-логи nginx;
- поведение при перезапуске и откате;
- доступ пользователей с минимальными правами;
- доставку уведомлений;
- наличие резервных копий для stateful volumes и внешних зависимостей.

## 7. Подготовьте откат

Для Deployments убедитесь, что предыдущий слот остаётся подходящей целью отката. Для контейнеров на основе image запишите неизменяемый digest. Для Git-сборок оставьте видимыми последний одобренный артефакт и развёрнутый commit.
