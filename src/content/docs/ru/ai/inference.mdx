Gateway Inference даёт команде единый API для AI-моделей разных поставщиков. Администратор подключает поставщиков и публикует одобренные модели под стабильными идентификаторами, а Gateway применяет права, лимиты и учёт использования. Клиентам не нужно хранить ключи каждого поставщика или менять конфигурацию при переключении между совместимыми источниками.

## Результат и владельцы

Владелец платформы выбирает поставщиков и модели, служба безопасности согласует правила обработки данных, а руководители команд задают бюджеты и доступ. Пользователь отвечает за свой токен Inference и за данные, которые отправляет выбранной модели.

Настройка успешна, если пользователь обращается к стабильному публичному идентификатору модели, расходы относятся к его учётной записи, лимиты срабатывают предсказуемо, а смена совместимого поставщика не требует перенастройки клиента. Gateway управляет маршрутизацией и учётом, но доступность и условия обработки данных по-прежнему зависят от поставщика.

## Путь администратора

1. Включите Inference в **Settings > General**.
2. Установите и проверьте ядро Inference.
3. Подключите поставщика по подписке, API или локальный источник моделей.
4. Дождитесь обнаружения моделей и доступных квот.
5. Опубликуйте логические модели с совместимыми источниками и техническими ограничениями.
6. Настройте лимиты по умолчанию и для отдельных пользователей.
7. Выдайте `feat:ai:use` ограниченной группе.

## Путь пользователя

Создайте токен `gwi_` в **Profile > Authorizations > Inference API tokens**. Для клиентов, совместимых с OpenAI, используйте базовый URL `/api/inference/v1`; для Anthropic SDK — `/api/inference`. Сопутствующий пакет может настроить Codex и Claude Code без ручного копирования параметров.

Тексты запросов и ответы моделей не сохраняются в журнале активности. Gateway хранит только нормализованные метаданные, объём использования, стоимость и сведения о маршрутизации. Приватные адреса поставщиков запрещены по умолчанию и требуют явного разрешения администратора.

## Поставщики и опубликованные модели

Подключение поставщика хранит учётные данные и состояние обнаружения. Опубликованная модель предоставляет стабильный публичный идентификатор и направляет запросы к одному или нескольким совместимым источникам. Для каждого источника точно укажите размер контекста, поддерживаемые форматы, модальности, цену и ограничения: одинаковое или похожее имя модели ещё не гарантирует совместимость.

После изменения поставщика дождитесь нового обнаружения моделей. Публикуйте модель только тогда, когда у неё есть хотя бы один доступный совместимый источник. Перед удалением поставщика проверьте все публичные модели, которые на него ссылаются.

## Маршрутизация запросов

Gateway проверяет токен `gwi_`, доступ к опубликованной модели и лимиты пользователя, затем выбирает совместимый источник и записывает метаданные учёта. Для связанных запросов система может сохранять привязку к одному источнику, если протоколу нужна непрерывность. После сбоя такая привязка освобождается или очищается по правилам запроса.

Потоковые и обычные запросы должны завершаться однозначным итоговым состоянием. Клиенту важно различать ошибку поставщика, отсутствие свободной ёмкости, превышение лимита, недействительный идентификатор продолжения и сетевой разрыв. Не повторяйте любой сбой вслепую на том же источнике.

## Лимиты и учёт

Сначала настройте системные значения по умолчанию, затем более узкие ограничения для отдельных пользователей. Проверьте лимиты запросов, токенов, одновременных обращений и бюджета через пользователя без административных прав. Перед финансовыми решениями сверяйте отчёт Gateway с отчётом поставщика.

Поставщики по подписке, по ключу API и локальные источники по-разному сообщают квоты и доступность. Обнаруженная свободная ёмкость не является договорной гарантией.

## Проверка клиента

1. Создайте отдельный пользовательский токен.
2. Получите список или выберите разрешённую опубликованную модель.
3. Отправьте один обычный текстовый запрос.
4. Отправьте один потоковый запрос и убедитесь, что он корректно завершился.
5. Проверьте неразрешённую модель и исчерпанный лимит.
6. Проверьте метаданные активности, использование, выбранный источник и маскирование чувствительных данных.
7. Безопасно проверьте отключение поставщика или переключение на резервный источник.

## Приватность и обработка сбоев

Gateway не записывает тексты запросов и ответы моделей в обычный журнал активности, но выбранный поставщик получает содержимое запроса. До открытия модели пользователям проверьте его условия хранения, обработки и географического размещения данных.

При сбое проверяйте по порядку: состояние ядра Inference, подключение поставщика, обнаруженные модели, настройки публикации, права токена, лимиты пользователя, доступную ёмкость и совместимость протокола. Перезапуск ядра не исправит неверные параметры поставщика или несовместимую модель.

## Безопасный запуск и откат

Сначала подключите одного поставщика и одну некритичную модель. Дайте доступ небольшой группе, задайте осторожные лимиты запросов и расходов и сравните учёт Gateway с отчётом поставщика. Добавляйте резервные источники только при реальной совместимости протокола, модальностей, размера контекста и поведения ответов. Более дешёвая модель с похожим именем не становится безопасной заменой автоматически.

Чтобы вывести модель из эксплуатации, прекратите выдавать новый доступ, предупредите потребителей, найдите клиентов публичного идентификатора и предоставьте проверенную замену. Если поставщик стал небезопасным или недоступным, отключите источник и проверьте маршрутизацию до повторного включения публичной модели. Не направляйте существующий идентификатор на существенно другую модель только ради успешного HTTP-ответа.

### Проверки оператора

- До публикации моделей убедитесь, что ядро Inference работает.
- Проверьте время последнего обнаружения и состояние квоты поставщика.
- Протестируйте заявленную совместимость с API OpenAI и Anthropic.
- Убедитесь, что потоковый ответ корректно закрывается, а прерванный запрос получает итоговую запись учёта.
- Проверьте исчерпание бюджета, запрещённую модель, отозванный токен и резервный источник.
- Регулярно анализируйте аномалии использования и сверяйте стоимость с поставщиком.
