Gateway Inference — отдельная плоскость данных на основе контролируемого inference core OpenCodex. Gateway владеет подключениями providers, публичными IDs моделей, правилами доступа, бюджетами, учётом и пользовательскими токенами.

## Результат и владельцы

Gateway Inference дает командам единый управляемый endpoint для одобренных AI-моделей, не заставляя каждого пользователя хранить credentials провайдера. Владелец платформы выбирает providers и модели, владелец безопасности согласует границы обработки данных, а руководители команд задают бюджеты и доступ. Пользователь отвечает за свой inference token и данные, отправляемые выбранной модели.

Успех означает, что одобренный пользователь вызывает стабильный публичный model ID, использование относится к нему, лимиты срабатывают предсказуемо, а смена provider не требует перенастройки клиента. Gateway управляет маршрутизацией и учетом, но не заменяет доступность, privacy terms или договорные гарантии capacity провайдера.

## Путь администратора

1. Включите Inference в **Settings > General**.
2. Установите и проверьте inference core.
3. Подключите subscription, API или local providers.
4. Дождитесь обнаружения моделей и quota.
5. Опубликуйте логические модели с совместимыми источниками и техническими ограничениями.
6. Настройте лимиты по умолчанию и для отдельных пользователей.
7. Выдайте `feat:ai:use` ограниченной группе.

## Путь пользователя

Создайте токен `gwi_` в **Profile > Authorizations > Inference API tokens**. Используйте `/api/inference/v1` для клиентов, совместимых с OpenAI, и `/api/inference` как base URL Anthropic SDK. Сопутствующий пакет может настроить Codex и Claude Code без ручного копирования конфигурации.

Prompts и output моделей не сохраняются в activity logs. Gateway хранит нормализованные метаданные, использование, стоимость и состояние маршрутизации. Приватные upstream URL запрещены по умолчанию и требуют явного разрешения администратора.

## Жизненный цикл provider и модели

Подключения providers хранят учётные данные и состояние обнаружения. Опубликованные модели предоставляют стабильные публичные IDs, направляя запросы к одному или нескольким совместимым источникам provider. Поддерживайте точные технические возможности, ограничения контекста, поддержку модальностей, pricing и ограничения каждого источника; одного имени модели provider недостаточно как контракта совместимости.

После изменения provider дождитесь обнаружения и публикуйте только модели как минимум с одним здоровым совместимым источником. Удаление provider не должно оставлять публичную модель, которая незаметно направляет запросы к несовместимому источнику.

## Маршрутизация запросов

Gateway аутентифицирует токен `gwi_`, разрешает опубликованную модель, проверяет лимиты пользователя и системы, выбирает совместимый источник provider и фиксирует нормализованные метаданные учёта. Sticky affinity может удерживать связанные запросы на одном источнике, когда протоколу нужна непрерывность; сбои освобождают или очищают affinity согласно жизненному циклу запроса.

Streaming- и non-streaming-запросы должны достигать одного terminal state. Клиенты должны различать ошибки provider, исчерпание ёмкости, rate limits, недействительные идентификаторы продолжения и сетевой разрыв, а не повторять каждый сбой на том же источнике.

## Лимиты и учёт

Сначала настройте системные значения по умолчанию, затем более узкие пользовательские переопределения. Проверьте лимиты запросов, токенов, concurrency и бюджета через пользователя без административных прав. Отчётность использования и стоимости — операционные метаданные; сверяйте их с отчётами provider до применения в финансовых решениях.

Subscription providers, API-key providers и local providers имеют разное поведение quota и доступности. Не представляйте обнаруженную ёмкость provider как договорную гарантию.

## Проверка клиента

1. Создайте отдельный пользовательский токен.
2. Получите список или выберите разрешённую опубликованную модель.
3. Отправьте один non-streaming текстовый запрос.
4. Отправьте один streaming-запрос и проверьте чистое terminal event.
5. Проверьте неразрешённую модель и исчерпанный лимит.
6. Проверьте activity metadata, использование, источник маршрутизации и маскирование.
7. Безопасно проверьте отключение provider или failover.

## Приватность и обработка сбоев

Gateway не записывает тела prompts или output моделей в обычные activity records, но выбранный provider получает содержимое запроса. Примените политику хранения, обработки данных и резидентности конкретного provider до публикации для пользователей.

При сбое запросов проверяйте по порядку состояние inference core, подключение provider, обнаруженные модели, правила публикации, области токена, лимиты пользователя, ёмкость и совместимость протокола. Перезапуск core не заменяет исправление недействительного контракта provider или модели.

## Решения rollout и rollback

Сначала подключите одного provider и одну некритичную опубликованную модель. Дайте доступ небольшой группе, задайте консервативные лимиты запросов и расходов и сравните учет Gateway с отчетом provider. Добавляйте fallback sources только при реальной совместимости протокола, модальности, контекста и поведения output. Более дешевая модель с похожим именем не становится безопасным failover автоматически.

Чтобы вывести модель из эксплуатации, прекратите выдавать новый доступ, предупредите потребителей, найдите клиентов публичного ID и предоставьте проверенную замену. Если provider стал небезопасным или недоступным, отключите source и проверьте routing state до повторного включения публичной модели. Не направляйте существующий ID на существенно другую модель только ради ответа `200`.

### Проверки оператора

- До публикации моделей убедитесь, что inference core сообщает healthy.
- Проверьте актуальность discovery timestamps и quota state provider.
- Протестируйте заявленные OpenAI-compatible и Anthropic-compatible paths.
- Убедитесь, что streaming закрывается корректно, а прерванные запросы получают terminal accounting state.
- Проверьте исчерпание бюджета, запрещенную модель, отозванный token и source failover.
- Регулярно анализируйте аномалии использования и сверяйте стоимость с provider.
