Gateway считает управляемые хосты и администраторов значимыми границами доверия. Он сокращает использование многоразовых учётных данных и зависимость от прямого shell-доступа с помощью исходящей регистрации daemon, идентичностей PKI, областей ресурсов, аудитируемых операций и ограниченных ролей daemon.

Основные принципы:

- одноразовая регистрация вместо многоразовых токенов Node;
- mTLS и закреплённая идентичность Gateway для управляемого транспорта;
- явные области ресурсов и отдельные права reveal/export/mount;
- зашифрованные секреты в хранилище и маскированный output по умолчанию;
- внутренние Containers Gateway исключены из пользовательских API жизненного цикла;
- отдельные идентичности приложений для привязок управляемых баз данных;
- поведение fail-closed, когда нельзя доказать владение, entitlement, состояние Node или совместимость provider;
- неизменяемая атрибуция аудита после изменений жизненного цикла учётной записи.

Gateway не является продуктом усиления защиты хоста, менеджером firewall, универсальным VPN или заменой engine-native резервных копий. Защищайте базовые операционные системы и сети независимо.

## Границы доверия

| Граница | Ответственность за безопасность |
| --- | --- |
| Хост Gateway | Защищать секреты приложения, доступ к базе данных, container runtime, persistent volumes и административный доступ |
| PostgreSQL и Redis | Сохранять приватными, аутентифицированными, резервируемыми и доступными только службам Gateway |
| Relay | Сохранять идентичность службы, подписанную политику, путь авторизации базы данных и владение публичным `9443/tcp` |
| Managed Node | Защищать идентичность daemon, службу systemd, локальный runtime, хранилище и права конкретной роли |
| Build Worker | Изолировать недоверенные сборки источника от обычных рабочих нагрузок и endpoints управления хостом |
| Ingress Node | Защищать закрытые ключи TLS, конфигурацию nginx, логи и публичный трафик |
| Database Node | Защищать учётные данные владельца, storage images, материалы Database CA и администрирование движка |
| External provider | Применять специфичные для provider меры защиты учётных данных, хранения, доступности и сети |

Администраторы и любой пользователь, способный управлять Docker socket хоста Gateway, имеют высокий уровень доверия. Внутренние Containers Gateway скрыты и защищены от обычных пользовательских API жизненного цикла, но это не превращает Docker-доступ уровня хоста в недоверенную границу.

## Идентичность и авторизация

Человеческие сеансы, API-токены, OAuth, MCP, сертификаты daemon, service identities, principals привязок баз данных, logging tokens и inference tokens — отдельные семейства учётных данных. Они не взаимозаменяемы. Backend повторно проверяет области, владение ресурсом, entitlements и текущее состояние, даже если UI скрывает действие.

Права с областью ресурса ограничивают объекты, которые пользователь может видеть или изменять. Чувствительные действия, включая раскрытие учётных данных, экспорт закрытого ключа, доступ к файлам хоста, console access и изменение secret, требуют отдельных полномочий сверх обычного чтения.

## Обработка секретов

Секреты зашифрованы в хранилище и маскируются в обычных ответах. Значения write-only нужно заменять, а не извлекать. Храните master keys отдельно от резервных копий базы данных, маскируйте логи и screenshots и не передавайте учётные данные через аргументы команд или URL репозитория.

Рабочие нагрузки управляемых баз данных получают идентичности отдельных привязок, а не учётные данные владельца. Целевой Docker daemon владеет приватным listener и разрешает в сети привязки только нужную стабильную идентичность рабочей нагрузки.

## Примеры fail-closed

Gateway отклоняет или откладывает операции, когда не может доказать текущее владение, capability Node, entitlement плана, совместимость provider/model, происхождение подписанного обновления, идентичность сетевого источника или необходимую авторизацию. Кэшированный инвентарь может оставаться видимым для диагностики, но не авторизует мутацию.

Сбои доступности нельзя «исправлять» созданием анонимных listeners, отключением проверки сертификатов, открытием приватных портов или копированием учётных данных владельца в рабочие нагрузки.

## Ограничения безопасности

Gateway не может защитить скомпрометированный endpoint администратора, вредоносный root хоста, владельца неограниченного Docker socket, скомпрометированный внешний identity provider или данные, намеренно экспортированные авторизованным пользователем. Используйте независимое усиление защиты хоста, сегментацию сети, защиту endpoints, резервное копирование и организационные меры.
