## Статус возможности

| Статус | Значение |
| --- | --- |
| Ready | Доступно в текущем продукте при выполнении требований плана и runtime |
| Ready, opt-in | Доступно, но скрыто или неактивно, пока администратор не включит функцию |
| In development | Входит в направление продукта или позиционирование плана, но пока недоступно в общем случае |
| Plan benefit | Коммерческое преимущество или преимущество уровня сервиса, а не функция runtime |

Включение в план и готовность runtime — разные вещи. Отметка для возможности **In development** означает, что план должен включить её после выпуска, а не что текущий экземпляр Gateway уже может её использовать.

Используйте этот указатель для трех вопросов оценки: владеет ли Gateway данным workflow, какая инфраструктурная prerequisite его обеспечивает и какой plan его допускает. Возможность может быть документирована и лицензирована, но недоступна в конкретной installation из-за неготового Node role, connector, provider или runtime capability.

## Текущие семейства продукта

- **Ingress:** Domains, Routes, TLS, access lists, обслуживание, health checks, управляемые upstream и размещение nginx.
- **Docker:** автономные Containers, сине-зелёные Deployments, инвентарь и жизненный цикл Compose, images, volumes, networks, registries, builds, migrations, archives, Tasks и monitoring.
- **Databases:** внешние подключения, управляемые PostgreSQL/Redis/ClickHouse, Explorers, monitoring, direct TLS и приватные привязки приложений.
- **Pages:** неизменяемые статические Deployments, Tags, Routes, previews и необязательные Git-сборки.
- **Nodes and Relay:** регистрация по ролям, отчёты capabilities, подписанные обновления, monitoring и работа Relay с несколькими участниками.
- **Identity:** пользователи, группы, MFA, OIDC, токены, OAuth, области ресурсов и impersonation.
- **Операционная видимость:** health, metrics, logs, Tasks, alerts, notifications, status pages, structured logging, audit и SIEM. Это связанные поверхности продукта, а не единый универсальный observability dashboard.
- **Automation and AI:** REST, OAuth, MCP, AI Workspace, scenarios, Plan Mode и Gateway Inference.
- **Security:** системная PKI, пользовательская Internal PKI, зашифрованные секреты, аудит, границы admission и проверки жизненного цикла fail-closed.

## Требования runtime

Entitlement плана не заменяет capability хоста. Secure Runtime требует здоровой capability gVisor, Git-сборки — выделенного Build Worker, управляемые базы данных — подготовленного Database Node, публичный Ingress — доступного Ingress Node, а приватные связи — здорового пути Relay.

Перед включением возможности в production используйте страницу функции для проверки предварительных условий, последствий жизненного цикла и поведения восстановления. Поведение планов описано в разделе [Планы и права по тарифу](/ru/reference/plans-and-entitlements/).

## Путь оценки

Для product evaluation начинайте с бизнес-пути, а не с максимального списка функций. Выберите одно публичное приложение, одну private data dependency, один managed Node role и одну operator identity. Докажите deployment, access control, клиентский трафик, monitoring, recovery и audit этого пути. Затем добавляйте Git builds, Pages, managed databases, AI или SIEM только когда они соответствуют целевой operating model.

Фиксируйте результат как:

- **supported and verified** в проверенной installation;
- **supported with an unmet prerequisite**;
- **plan-restricted**;
- **in development**; или
- **outside Gateway's product boundary**.

Так roadmap positioning, disabled UI control и неготовая runtime capability не смешиваются в один статус.

## Граница продукта

Gateway координирует инфраструктурные ресурсы и их поддерживаемый lifecycle. Он не заменяет Kubernetes, infrastructure-as-code, профессиональные monitoring/SIEM, host security, network firewalls, engine-native database tooling или disaster-recovery systems. Используйте эти системы рядом с Gateway, если организации нужна их глубина. Ценность Gateway — согласованный слой ownership, authorization, workflow и audit для поддерживаемых ресурсов, а не попытка поглотить все инфраструктурные дисциплины.
