Планируйте плоскость управления отдельно от хостов управляемых рабочих нагрузок.

## Хост Gateway

Используйте поддерживаемый Linux-хост с Docker Engine и Docker Compose. Зарезервируйте постоянное хранилище для PostgreSQL, загружаемых артефактов, сертификатов, конфигурации и необязательных структурированных логов. Точная ёмкость зависит от хранения истории, артефактов Pages, объёма сборок и журнала активности; в production следует отслеживать рост диска и создавать резервные копии как данных, так и ключей шифрования.

Для публичной установки требуется:

- стабильный канонический URL;
- входящий HTTP/HTTPS для веб-приложения;
- входящий `9443/tcp` к Relay, если управляемые Node подключаются через публичную сеть;
- корректные системные часы и работающий DNS;
- исходящий доступ к настроенным провайдерам удостоверений, ACME, систем контроля версий, registry, обновлений и AI.

## Роли Node

Выбирайте только нужные роли:

- **nginx node:** Ingress, материализация TLS, Pages, логи и метрики;
- **Docker node:** Containers, Deployments, Compose, файлы, логи и состояние runtime;
- **database node:** управляемые экземпляры PostgreSQL, Redis или ClickHouse;
- **Build Worker:** изолированное выполнение BuildKit/containerd без сокета Docker Engine;
- **monitoring node:** сбор данных, специфичный для мониторинга;
- **Relay Pool member:** необязательная устойчивость и дополнительная ёмкость плоскости данных.

Не размещайте Build Workers на хостах с посторонними рабочими нагрузками или многоразовыми учётными данными. Считайте внешнюю VM или непривилегированный контейнер границей безопасности.

## DNS и сертификаты

Решите, будет ли Gateway управлять DNS через Cloudflare или только проверять записи, которыми управляют извне. Для HTTP-01 требуется публичный порт 80 на назначенном Ingress Node. Для DNS-01 требуется настроенная интеграция с DNS-провайдером.

## Решения для production

1. Канонический публичный URL и модель завершения TLS.
2. Методы аутентификации и владелец первой учётной записи администратора.
3. Место хранения резервных копий и ответственный за восстановление.
4. Разделение ролей Node и политика firewall.
5. Модель работы с доменами и DNS.
6. Требуемые права по тарифному плану.
7. Срок хранения логов и требования SIEM.
8. Нужны ли для Git-сборок выделенные Build Workers.

Перед изменением firewall см. раздел [Порты и сеть](/ru/reference/ports-and-network/).
