Поддерживаемый сценарий установки использует установщик Gateway и Docker Compose. Выполняйте точную команду из канала релизов или со страницы загрузки продукта, а не копируйте старую команду из задачи или чата.

## Перед установкой

- Убедитесь, что хост соответствует [требованиям](requirements.mdx).
- Создайте DNS-запись для предполагаемого URL Gateway.
- Решите, будет ли Gateway обслуживать нативный HTTPS или работать за существующим обратным прокси.
- Подготовьте постоянное хранилище для резервных копий.
- Не раскрывайте код настройки, сгенерированный установщиком: это одноразовые учётные данные bootstrap.

## Установка

1. Запустите текущий подписанный установщик от имени администратора на выбранном хосте.
2. Перед первым использованием в production проверьте сгенерированный файл окружения.
3. Запустите сгенерированный Compose Project.
4. Убедитесь, что приложение, PostgreSQL, Redis и службы Relay работоспособны.
5. Откройте канонический URL Gateway и введите код настройки.

## Нативный HTTPS и обратные прокси

Используйте один авторитетный публичный URL. Если внешний прокси завершает TLS, корректно передавайте исходные схему и host и оставляйте канонический URL Gateway равным адресу, видимому извне. Неправильные канонические URL ломают cookie, перенаправления OAuth/OIDC, WebSocket-соединения и сгенерированные команды регистрации.

## Проверка установки

До добавления Node убедитесь, что:

- страница входа/настройки загружается без предупреждений браузера о сертификате;
- служба Relay работоспособна и владеет публичным `9443/tcp`;
- PostgreSQL и Redis сохраняются после перезапуска Compose;
- системные часы и часовой пояс настроены правильно;
- мастер настройки может создать первого администратора;
- на хосте достаточно свободного места для выбранной модели хранения истории.

Продолжите с раздела [Первоначальная настройка](initial-setup.mdx).
