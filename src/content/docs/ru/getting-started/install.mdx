Публичный установщик подготавливает хост, при необходимости сам устанавливает Docker, запускает полный стек Gateway и передаёт дальнейшую настройку браузеру. Для обычной первой установки не нужно самостоятельно создавать Compose-файл или заранее устанавливать Docker.

## Что потребуется до начала

Выберите отдельный Linux-хост или VM, соответствующую [требованиям по ресурсам](/ru/getting-started/requirements/). Автоматическая установка Docker поддерживает семейства Debian, Ubuntu, Fedora, CentOS и RHEL. Также нужны:

- учётная запись с root-доступом или рабочим `sudo`;
- исходящий доступ к сервису обновлений Gateway, container registries и репозиториям пакетов Docker;
- `curl` и OpenSSL;
- решение о конечном URL Gateway и DNS-записи;
- входящий доступ к web listener и Relay path, описанным в разделе [Порты и сетевые пути](/ru/reference/ports-and-network/).

Предварительно установленные Docker Engine и Docker Compose **не требуются**. Если рабочий Docker уже есть, установщик использует его. В противном случае он подключает официальный репозиторий Docker, устанавливает Docker Engine и Compose v2 plugin и запускает службу Docker. На хостах с конфликтующими пакетами дистрибутива или Podman compatibility packages шаг установки Docker может заменить такие пакеты, поэтому используйте отдельный хост Gateway, а не машину с несвязанными рабочими нагрузками.

## Установите Gateway

Подключитесь к выбранному хосту и выполните:

```bash
curl -sSL https://thesqlabs.com/gateway/install.sh | bash
```

При новой интерактивной установке выберите, как Gateway будет слушать порт 3000:

- **Internal HTTPS** используется по умолчанию. Gateway применяет сертификат, выпущенный собственным System CA.
- **HTTP** подходит, когда доверенный reverse proxy завершает TLS, а внутренний участок намеренно оставлен незашифрованным.

При неинтерактивном запуске HTTPS выбирается автоматически. Режим можно указать явно:

```bash
# Internal HTTPS, также режим по умолчанию
curl -sSL https://thesqlabs.com/gateway/install.sh | bash -s -- --https

# HTTP за доверенным TLS-terminating proxy
curl -sSL https://thesqlabs.com/gateway/install.sh | bash -s -- --http
```

Чтобы проверить выбранный подписанный релиз и план действий без изменения хоста, используйте dry run:

```bash
curl -sSL https://thesqlabs.com/gateway/install.sh | bash -s -- --dry-run
```

## Что изменяет установщик

Каталог установки по умолчанию — `/opt/gateway`. Установщик проверяет выбранный релиз, создаёт environment и Compose foundation, загружает неизменяемые образы приложения и Relay, создаёт постоянное хранилище и запускает Gateway, PostgreSQL, Redis, локального участника Relay и приватный внутренний registry для поддерживаемых build workflows.

Считайте этот хост частью доверенной вычислительной базы Gateway. Приложение намеренно получает управление Docker-хостом для подписанных обновлений, восстановления, housekeeping и дополнительных управляемых сервисов. Изолируйте Gateway в собственной VM или на отдельном доверенном хосте; не размещайте там несвязанные нагрузки или учётные данные.

## Завершите настройку в браузере

Когда стек станет работоспособным, терминал выведет:

- URL, который нужно открыть;
- fingerprint System CA Gateway;
- одноразовый setup code, действующий 24 часа;
- reset command, выпускающую новый код, если настройка истекла.

Setup code показывается открытым текстом один раз и не записывается в `.env` или базу данных. Вводите его только на странице настройки Gateway; не отправляйте его в чат, задачи, логи или screenshots. Browser wizard настраивает canonical URL, endpoints сети Nodes, аутентификацию, первого администратора, structured logging и необязательный AI Workspace.

После завершения установщика продолжите с раздела [Первоначальная настройка](/ru/getting-started/initial-setup/).

## Проверьте установку

Установка завершена, когда browser setup page открывается, а обязательные сервисы стека находятся в рабочем состоянии. Для операторской проверки:

```bash
cd /opt/gateway
sudo docker compose ps
```

Все обязательные сервисы должны работать. Локальный health endpoint можно проверить согласно выбранному transport:

```bash
curl -kfsS https://127.0.0.1:3000/health
# или для HTTP-установки:
curl -fsS http://127.0.0.1:3000/health
```

Не добавляйте production Nodes, пока wizard не завершён, canonical URL не подтверждён и обычный вход пользователя не работает.

## Если установка завершилась ошибкой

Перед повторным запуском прочитайте `/tmp/gateway-install.log` и финальное сообщение установщика. После исправления проблем сети, пакетов, диска или registry установщик можно запускать повторно: он распознаёт существующее управляемое развёртывание и при обновлении сохраняет постоянную конфигурацию Gateway.

Если сервисы созданы, но Gateway не стал healthy, проверяйте ограниченный статус Compose и логи из `/opt/gateway`, а не удаляйте volumes и не перевыпускайте учётные данные. Сохраните `.env`, PostgreSQL, identity/state Relay, `gateway_data` и master encryption key. Их удаление превращает восстанавливаемую проблему установки в потерю данных или идентичности.
