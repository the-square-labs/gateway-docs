# Добавьте первый Node

Управляемые демоны инициируют исходящие аутентифицированные соединения с Gateway. Не копируйте на Node многоразовые учётные данные API.

![Диалог добавления Node с выбранной ролью Relay и настроенным публикуемым адресом](/screenshots/product-tour/node-enrollment-relay.png)

## Основной сценарий

1. Откройте **Nodes** и создайте Node.
2. Выберите нужную роль и профиль runtime.
3. Скопируйте сгенерированную одноразовую команду установщика.
4. Выполните её на целевом Linux-хосте.
5. Дождитесь появления Node со статусом **Online**.
6. Откройте страницу сведений о Node и проверьте hostname, версию, возможности, service address и последние метрики.
7. Используйте встроенную проверку обновлений, чтобы убедиться, что демон может обратиться к каналу релизов.

Установщик фиксирует идентичность Gateway. Не удаляйте сгенерированный отпечаток сертификата, чтобы обойти проблему подключения.

## Проверки для отдельных ролей

- **nginx:** проверьте валидацию конфигурации nginx, публичный service address, порты 80/443 и доступ к логам.
- **Docker:** проверьте доступ к Docker Engine, синхронизацию инвентаря, возможности runtime и необязательное обнаружение GPU.
- **database:** проверьте требования к хранилищу и убедитесь, что хост выделен под управляемые базы данных.
- **builder:** проверьте работоспособность BuildKit/containerd, применение ограничений ресурсов и выбранный профиль исходящего трафика.

## Обработка сбоев

Если регистрация не удаётся, проверьте логи службы демона, системное время, DNS, исходящую доступность Gateway Relay и точную сгенерированную команду. Удаляйте и создавайте заново Node в состоянии ожидания только если намеренно хотите получить новую идентичность; не используйте повторно старый токен регистрации.
