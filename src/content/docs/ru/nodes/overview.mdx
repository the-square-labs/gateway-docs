# Nodes и демоны

Node — это долговечная идентичность Gateway для одной роли управляемого хоста. Демон передаёт hostname, версию, состояние, инвентарь, метрики, service addresses и возможности, специфичные для роли, через исходящий аутентифицированный сеанс.

Gateway разделяет ответственность Ingress, Docker, Databases, Build Worker, Monitoring и Relay. Выбирайте точную роль при регистрации и не используйте идентичность демона повторно для другой границы доверия.

Страница сведений о Node — основное место для проверки соединения, несовпадений возможностей, готовности к обновлению, нагрузки на ресурсы, последних операций и последнего синхронизированного состояния. Устаревший снимок подходит для диагностики только чтения, но никогда не авторизует мутацию.

## Идентичность и состояние

Создание Node сначала формирует ожидающую долговечную идентичность. Сгенерированный токен регистрации одноразовый и привязан к этой идентичности. Успешная регистрация устанавливает сертификат демона и переводит Node в состояние управляемого хоста в сети; удаление и повторное создание записи намеренно создаёт другую идентичность.

Gateway различает несколько видов состояния:

- **желаемое состояние:** то, что операторы настроили в Gateway;
- **сообщённое состояние:** последний инвентарь и отчёт о возможностях, подтверждённые демоном;
- **состояние runtime:** текущее состояние службы и активные операции;
- **кэшированный снимок:** последняя известная модель чтения, используемая при кратковременной недоступности Node.

Кэшированные данные помогают диагностировать проблему, но никогда не авторизуют мутацию. Действия, требующие актуального состояния хоста, завершаются с отказом, если демон отключён или его возможности устарели.

## Границы ролей

| Роль | Владеет |
| --- | --- |
| Ingress | конфигурацией nginx, сертификатами, Routes, телеметрией доступа и трафика |
| Docker | Containers, Deployments, Compose, images, volumes, networks, builds и endpoints миграции |
| Build Worker | изолированным выполнением сборок Git и допуском артефактов |
| Databases | движками управляемых баз данных, образами хранения, прямыми endpoints и телеметрией баз данных |
| Monitoring | метриками хоста без доступа к жизненному циклу рабочих нагрузок |
| Relay | аутентифицированным транспортом Node и поддерживаемыми приватными туннелями |

Не считайте обозначения ролей косметикой. Каждый установщик, профиль демона, набор возможностей, артефакт обновления и граница прав отличается.

## Эксплуатационные проверки

Для каждого production Node подтвердите:

- hostname и отображаемое имя указывают на правильный физический хост;
- service addresses доступны предназначенным им соседям;
- версия и состояние совместимости актуальны;
- ожидаемые возможности работоспособны, а не просто присутствуют;
- для нагрузки на storage, memory, CPU и disk настроены оповещения;
- процедуры обновления и восстановления документированы;
- Node входит в правильную папку и области прав.
