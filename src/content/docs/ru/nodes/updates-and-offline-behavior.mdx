Проверяйте совместимость перед обновлением Gateway, Relay и демонов. Применяйте подписанные обновления демона через жизненный цикл Node и проверяйте переподключение, версию, инвентарь, логи, состояние и управляемые binding.

Когда Node отключается, рабочие нагрузки могут продолжать работать локально, но мутации Gateway блокируются. Диагностируйте доступность хоста, службу демона, системное время, идентичность сертификата, DNS и исходящий доступ к Relay. Не удаляйте запись Node, пока старый демон ещё может переподключиться.

После восстановления проверьте реконсиляцию желаемого состояния для Routes, рабочих нагрузок, database bindings, материалов сертификатов и мониторинга. Одного зелёного статуса соединения недостаточно, чтобы подтвердить восстановление всех зависимых ресурсов.

## Перед обновлением

1. Прочитайте заметки о выпуске компонента и минимальную версию совместимости.
2. Убедитесь, что канал обновлений выбран осознанно: Stable для production-релизов или Preview для явно принятых предварительных версий.
3. Проверьте, что Node в сети и не выполняет конфликтующую операцию жизненного цикла.
4. Зафиксируйте текущую версию, возможности, активные рабочие нагрузки и последние ошибки.
5. Для Relay Pool выводите из обслуживания и обновляйте по одному участнику.
6. Убедитесь, что оператор сможет попасть на хост, если автоматическое восстановление завершится ошибкой.

Gateway и демоны проверяют подписанные манифесты обновлений и контрольные суммы. Не заменяйте неудачное подписанное обновление неподписанным бинарным файлом, скопированным с другого хоста.

## Проверка обновления

После перезапуска демона проверьте не только его версию:

- аутентифицированное переподключение и свежее время last-seen;
- полный отчёт о возможностях;
- обновление инвентаря и метрик;
- состояние служб, специфичное для роли;
- реконсиляцию ожидающих Tasks;
- Routes, сертификаты, рабочие нагрузки, Compose Projects и database bindings, принадлежащие этому Node;
- ожидаемое создание или снятие оповещений.

## Поведение при отключении по зонам ответственности

Отключение управляющего соединения не останавливает автоматически службы на хосте. nginx, Containers, управляемые базы данных и другие ранее применённые службы могут продолжать работу из локального состояния. Gateway блокирует мутации, требующие живого владельца, и показывает кэшированный инвентарь только для диагностики.

Database bindings могут продолжать работу через исправный Relay и путь к базе данных во время перезапуска только приложения Gateway. Сбой Relay — другое событие: он прерывает новые подключения приватных связей и управляющий трафик к управляемым Nodes, даже если локальные рабочие нагрузки продолжают работать.

## Последовательность восстановления

1. Восстановите питание и сетевую доступность хоста.
2. Проверьте системное время, DNS и соединение с endpoint Relay.
3. Изучите systemd unit демона и ограниченные логи.
4. Убедитесь, что сертификат демона и идентичность Node не заменялись.
5. Дождитесь переподключения и свежего инвентаря.
6. Перед повторной попыткой проверьте неудачные или прерванные операции.
7. Проверьте каждое семейство зависимых ресурсов, принадлежащих Node.

Не удаляйте отключённый Node только для исчезновения предупреждения. Удаление меняет долговечное владение и может оставить всё ещё работающий старый демон без безопасной реконсиляции.
