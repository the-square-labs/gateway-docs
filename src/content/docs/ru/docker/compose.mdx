# Compose Projects

Gateway обнаруживает внешние Docker Compose-приложения и может управлять одновузловыми Compose Projects как долговечными ресурсами. Проект объединяет службы, конфигурацию, неизменяемые ревизии, операции жизненного цикла, логи, Routes и database bindings под одной стабильной идентичностью.

Внешнее обнаружение доступно на любом плане. Для создания или принятия во владение управляемого одновузлового проекта требуется Personal или выше. Сборки Compose из Git требуют Business или Enterprise и подключённого выделенного Build Worker.

## Внешние и управляемые проекты

**External**-проект обнаруживается по каноническим Docker labels. Gateway показывает инвентарь, состояние, состояние служб, мониторинг и агрегированные логи, но не читает Compose-файл хоста и не изменяет проект, пока оператор явно не примет его во владение.

**Managed**-проект хранит в Gateway авторский Compose YAML, переменные, защищённые ключи секретов и неизменяемые ревизии. Docker daemon применяет выбранную ревизию через зафиксированный Compose runtime Gateway. Управляемый жизненный цикл остаётся одновузловым; кластеры приложений на нескольких Nodes и масштабирование реплик на одном Node имеют статус **In development**.

Дочерние Containers проекта, именованные volumes и сети, не отмеченные как external, управляются через Compose Project. Они скрыты или защищены от конфликтующих автономных операций жизненного цикла. Images и явно external или общие ресурсы остаются глобальными ресурсами Docker.

## Создайте управляемый проект

1. Откройте **Docker > Compose** и выберите **New Project**.
2. Выберите подключённый Docker Node с возможностью Compose.
3. Введите полную однофайловую Compose-конфигурацию.
4. Укажите несекретные переменные и отдельно перечислите защищённые ключи секретов.
5. Запустите валидацию и устраните неподдерживаемые параметры, отсутствующие переменные, конфликты портов или нарушения политики.
6. Создайте проект и доведите первую операцию apply до завершения.
7. Проверьте все ожидаемые службы, состояние, сеть, volumes и агрегированный поток логов.

Проекты, созданные вручную, работают только с image: образы должны быть заранее доступны для загрузки целевым Node. На планах Business и Enterprise можно подключить разрешённый источник Git. В этом случае ограниченные секции Compose `build` разрешаются изолированными Build Workers, к результату применяется политика уязвимостей, а перед развёртыванием одобренные digest фиксируются в неизменяемой ревизии.

## Примите внешний проект во владение

Принятие во владение — это явная передача ответственности. Откройте обнаруженный проект, выберите **Adopt** и передайте полную конфигурацию, которой должен владеть Gateway. Gateway проверит её и подготовит первую неизменяемую ревизию до применения.

Убедитесь, что переданный YAML соответствует работающим службам приложения, volumes, сетям, переменным и секретам. Gateway никогда не доверяет пути хоста, переданному через label, как источнику конфигурации. После принятия во владение последующие изменения должны проходить через новые ревизии, а не через прямое изменение дочернего контейнера.

## Ревизии и жизненный цикл

Редактирование конфигурации создаёт новую неизменяемую ревизию. Используйте **Pull & Apply**, чтобы загрузить нужные образы и применить активную ревизию, **Start** или **Stop** — для управления жизненным циклом проекта, а **Change revision** — чтобы повторно применить прежнюю корректную ревизию. Неактивные ревизии можно удалить, если ни одна операция их не использует; активную ревизию удалять нельзя.

## Routes и database bindings

Routes и Secure Links могут обращаться к управляемой Compose-службе по стабильным идентичностям проекта и службы, а не по эфемерному имени контейнера. Managed database bindings обновляют ревизию проекта, сохраняя авторскую конфигурацию и защищённые секреты. Удаление службы или binding должно проходить через новую ревизию, чтобы Gateway мог безопасно выполнить реконсиляцию зависимых связей.

## Drift и диагностика

Gateway сообщает о drift, когда наблюдаемое состояние runtime больше не соответствует активной ревизии. Перед повторной попыткой проверьте текущую операцию, соединение Docker Node, возможность Compose, доступ к загрузке image, логи служб, переменные, секреты и диагностику daemon.

Не исправляйте управляемый проект удалением его дочерних Containers, сетей или метаданных ревизии вручную. Для внешнего проекта вносите изменения через исходный Compose-процесс до завершения принятия во владение.

## Удалите проект

Остановите управляемый проект и удалите зависимые Routes или bindings до его удаления. Удаление записи проекта Gateway удаляет историю управляемых ревизий, но runtime-volumes автоматически не удаляются. Отдельно создайте резервную копию или удалите постоянные данные в соответствии с требованиями хранения приложения.
