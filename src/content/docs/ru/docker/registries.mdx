Registry поставляют образы, которые запускают Docker Nodes, и артефакты, которые публикуют Build Workers. Gateway хранит учётные данные registry и решения о доступе отдельно от конфигурации рабочей нагрузки, использующей image. Благодаря этому оператор может ротировать доступ к registry, не раскрывая пароль в Container, Deployment или определении источника.

## Настройте доверенный доступ

Храните учётные данные приватного registry в Gateway и ограничивайте их нужным путём сборки или runtime. Настраивайте отдельный доверенный origin token-service только если registry намеренно делегирует Bearer-аутентификацию этой службе. До production rollout проверьте endpoint registry, доступ к репозиторию и доверие к сертификату.

Никогда не помещайте пароли registry в ссылки на image, URL Git, аргументы сборки, логи, имена архивов или screenshots. Если аутентификация завершается ошибкой, диагностируйте учётные данные registry, права репозитория, конфигурацию token-service и доступность сети целевого Node, а не перезапускайте рабочую нагрузку снова и снова.

## Поведение внутреннего registry

Внутренний Distribution registry Gateway хранит одобренные артефакты сборки по неизменяемому digest. Он удерживает артефакты, необходимые активным рабочим нагрузкам, слотам отката, выполняющимся операциям, закреплённым ссылкам и недавним успешным сборкам. Для внутреннего использования Gateway ему не нужен публичный домен.

Наличие image во внутреннем registry не делает его публичным релизом. Рабочая нагрузка всё ещё должна быть настроена на этот digest, успешно загрузить его на целевом Node и пройти эксплуатационную проверку.

## Необязательный доступ внешнего Docker-клиента

Доступ внешнего Docker-клиента — отдельное право по тарифному плану и конфигурация Ingress. Для него нужны выбранное размещение nginx, Domain, TLS-сертификат и токен с областью репозитория или действия. Каждый запрос токена повторно проверяет текущую авторизацию и право по плану, поэтому отзыв любого из них действует для последующих обращений.

Включайте внешний доступ только когда он нужен реальному клиентскому процессу. До использования в автоматизации проверьте TLS, аутентификацию и минимальные права репозитория/действия через непроизводственный клиент. Удаление конфигурации Ingress прекращает доступ клиента, но не удаляет внутренние сохранённые артефакты.

## Рекомендации при инцидентах и очистке

При неудачной загрузке сначала подтвердите точный digest image, сопоставление registry, область учётных данных и сетевой путь Node. Для неожиданного image сравните его digest с одобренной записью сборки, а не доверяйте tag. Перед удалением конфигурации registry определите рабочие нагрузки и кандидатов для отката, которым она ещё нужна; сначала переведите их на одобренную альтернативу.
