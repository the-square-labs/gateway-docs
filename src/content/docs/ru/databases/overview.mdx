# Обзор баз данных

Gateway объединяет две разные модели баз данных в одной операционной поверхности: сохранённые внешние подключения и управляемые экземпляры баз данных. Различие заключается во владении. Внешнее подключение фиксирует доступ к сервису, который эксплуатируется в другом месте; управляемый экземпляр имеет контролируемый Gateway жизненный цикл на Node профиля Databases.

## Модель ресурсов

Управляемые экземпляры PostgreSQL, Redis и ClickHouse по умолчанию приватны. Gateway координирует конфигурацию движка, хранилище, учётные данные, состояние, логи, операции и привязки приложений. Выбранный Database Node запускает движок, а Gateway сохраняет желаемое состояние ресурса и его связи с рабочими нагрузками.

Внешнее подключение не передаёт Gateway владение базой данных. Gateway хранит конфигурацию подключения и учётные данные в зашифрованном виде с явным контролем прав, но доступность внешней базы данных, резервное копирование, политика доступа и жизненный цикл движка остаются ответственностью её оператора.

## Приватный доступ по умолчанию

Используйте привязку приложения, когда управляемой рабочей нагрузке нужен доступ к управляемой базе данных. Привязка предоставляет отдельную идентичность движка с минимальными правами и обращается к базе данных через приватный listener, принадлежащий daemon. Listener создаётся непосредственно целевым Docker daemon в выделенной bridge network; отдельного сервиса на стороне привязки для эксплуатации нет.

Этот транспорт отличается от коннектора Secure Link между nginx и рабочей нагрузкой. Secure Link остаётся отдельным компонентом для собственных задач Ingress и Relay. Не воспринимайте сбой привязки как признак того, что компонент Secure Link следует удалить, пересоздать или настроить как транспорт базы данных.

Прямая публикация TCP — явная opt-in функция для внешних клиентов. Она не открывает firewall хоста автоматически и должна включаться только для определённого клиентского пути с подходящими учётными данными и доверием к сертификату. Публикация экземпляра не меняет приватную модель привязок, используемую рабочими нагрузками.

## Границы жизненного цикла и эксплуатации

Страница сведений о базе данных объединяет состояние, метрики, настройки движка, учётные данные, сертификаты, изменение размера, pause/unpause, restart, логи и доступные функции Explorer или Console. Доступные действия зависят от движка, соединения с Node, состояния экземпляра и выданных вам прав.

Pause сохраняет данные, намеренно отключая вычисления движка. Приостановленный экземпляр не предоставляет обычные данные состояния, метрики, Explorer или Console, пока не будет возобновлён. Restart полезен как контролируемая эксплуатационная операция; он не исправляет нерешённые проблемы хранилища, аутентификации или Node.
