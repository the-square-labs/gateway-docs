# Secure Links

Secure Links соединяют поддерживаемые управляемые ресурсы Gateway, не превращая назначение в обычный публичный endpoint.

## Database bindings

Managed database binding соединяет один автономный Container, Deployment или Compose service с одной управляемой базой данных. Gateway создаёт отдельную engine identity для binding и передаёт только данные подключения, относящиеся к этому binding. Учётные данные владельца базы данных не раскрываются рабочей нагрузке.

Пересоздание рабочей нагрузки сохраняет доступность binding, поскольку авторизация следует стабильной идентичности ресурса Gateway. Удаление binding выводит его engine identity из эксплуатации через согласованный жизненный цикл; Gateway не должен оставлять осиротевшие роли или пользователей.

## Ingress upstream links

Routes и Additional Routes могут направлять трафик к поддерживаемым Docker-ресурсам через Secure Link, принадлежащий Route. Расширенные конфигурации могут использовать отдельно управляемые дополнительные binding. Binding, принадлежащий Route, виден для диагностики, но не может быть удалён независимо от владельца.

## Что Secure Links не делают

- Это не универсальный VPN и не overlay-сеть.
- Они не обеспечивают произвольную переадресацию TCP или SSH.
- Они не открывают firewall хоста автоматически.
- Они не отменяют необходимость аутентификации на уровне приложения, если её требует протокол назначения.

## Эксплуатационные проверки

Для Ingress-связей отслеживайте состояние коннектора Secure Link вместе с доступностью Relay, задержкой настройки, активными потоками, пропускной способностью, состоянием завершения и отклонёнными подключениями. Для managed database bindings отслеживайте слушатель, принадлежащий демону, и состояние реконсиляции binding, а не ищите контейнер коннектора. При сбое сначала диагностируйте идентичность и реконсиляцию желаемого состояния, а не пересоздавайте ресурсы вручную.
