Ресурсы Gateway имеют стабильные идентичности, отдельные от изменяемых runtime-имён или идентификаторов контейнеров.

## Стабильные идентичности

Права, binding, настройки источника, конфигурация health и состояние миграции привязаны к идентичности ресурса Gateway. Пересоздание управляемой рабочей нагрузки сохраняет нужную идентичность; явное удаление снимает связанные гранты, поэтому последующий ресурс с тем же именем не получает доступ случайно.

## Границы владения

- Compose Project владеет своими service-контейнерами, именованными volumes и сетями, не отмеченными как external.
- Сине-зелёный Deployment владеет обоими runtime-слотами и состоянием rollout.
- Управляемая база данных владеет своим database Container и identity владельца engine.
- Database binding владеет отдельной application identity с минимальными правами.
- Route или Additional Route может владеть своим Secure Link binding.
- Внутренние Containers, принадлежащие Gateway, недоступны API жизненного цикла пользователя.

Эти границы не позволяют API нижнего уровня обходить жизненный цикл верхнего уровня, создавшего ресурс.

## Папки и навигация

Папки организуют ресурсы и могут участвовать в ограничении доступа. Они не изменяют runtime-сеть или владение. Результаты поиска и command palette должны вести на каноническую страницу ресурса, а не на дочерние объекты реализации.

## Внешние ресурсы

Созданные извне Compose Projects можно обнаруживать по каноническим Docker labels. Они остаются доступными только для чтения, пока оператор не примет их с полной YAML-конфигурацией. Внешними базами данных по-прежнему управляет оператор; Gateway хранит и проверяет их подключение, не заявляя владение жизненным циклом.
