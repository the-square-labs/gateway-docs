Gateway отделяет централизованные намерения и идентичность от выполнения операций на хостах.

```text
Users and automation
        |
  HTTPS / WebSocket
        |
Gateway application ---- PostgreSQL / Redis
        |
 internal authenticated gRPC
        |
Gateway Relay :9443
        |
 outbound managed-daemon sessions
        |
nginx / Docker / database / builder / monitoring hosts
```

## Плоскость управления

Приложение Gateway владеет пользователями, группами, областями, определениями ресурсов, желаемым состоянием, записями аудита, зашифрованными учётными данными интеграций, состоянием долгих операций и решениями по восстановлению. PostgreSQL — надёжный долговечный источник истины. Redis используется для ограниченной координации, кэширования, очередей и, где применимо, краткоживущих резервирований.

## Relay

Relay — единственный публичный владелец `9443/tcp`. Управляемые демоны подключаются исходящим соединением через аутентифицированный транспорт. Приложение сохраняет свой gRPC-слушатель внутренним. Если Relay недоступен, новые операции с управляемыми Node и новые подключения приватных туннелей завершаются с отказом; существующие сеансы плоскости данных могут продолжаться только там, где это допускают их протокол и модель авторизации.

## Управляемые демоны

Каждый демон выполняет ограниченную роль. Демон Docker не может стать демоном базы данных из-за изменения клиентского запроса, а API жизненного цикла пользователей не должны изменять внутренние Containers, принадлежащие Gateway. Демоны сообщают о возможностях и инвентаре; плоскость управления авторизует операцию до её отправки.

## Плоскость данных

Публичный трафик обслуживают Node nginx. Приватные пути от приложения к базе данных и от nginx к рабочей нагрузке используют Secure Links и идентичности коннекторов. Gateway Inference использует отдельно контролируемое inference core, доступное только через прокси Gateway.

## Модель отказов

Пока Node отключён, представления для чтения могут использовать очищенные снимки последнего известного состояния. Мутации остаются недоступными. Желаемое состояние сохраняется надёжно, поэтому Gateway может выполнить реконсиляцию после перезапуска приложения, Relay, демона или Node.
