Раздел **Storage** управляет ресурсами двух видов. **Подключение к хранилищу** хранит доступ к объектному или файловому хранилищу, которое работает в другом месте. **Управляемое хранилище** — объектное хранилище MinIO, которое Gateway создаёт и запускает на ноде хранилища. Оба вида требуют тарифа Personal или выше. Хранилища служат местом назначения для [резервного копирования баз данных](/ru/databases/backups/), а управляемое хранилище может предоставить рабочим нагрузкам приватный доступ, ограниченный отдельными бакетами.

| Вопрос | Подключение к хранилищу | Управляемое хранилище |
| --- | --- | --- |
| Кто эксплуатирует службу | Провайдер или ваша команда хранения данных | Gateway — как MinIO на одной или нескольких нодах хранилища с ограниченными дисками |
| Протоколы | S3 (AWS S3, Cloudflare R2, MinIO и другие S3-совместимые службы), SFTP, FTP, FTPS | S3 с необязательными службами приёма соединений FTP и SFTP |
| Обозреватель объектов | Да | Да |
| Место назначения резервных копий | Да | Да |
| Ключи доступа и привязки рабочих нагрузок | Нет | Да |
| Публичный доступ | Неприменимо | По умолчанию приватное; публичные службы приёма соединений S3, FTP и SFTP включаются явно |
| Удаление | Удаляет только сохранённое подключение в Gateway | Удаляет службу и стирает её данные на каждом участнике |

## Подключения к хранилищам

Выберите **Add Storage** и укажите провайдера:

| Провайдер | Параметры подключения |
| --- | --- |
| AWS S3, Cloudflare R2, MinIO, Other (S3-compatible) | Регион, идентификатор ключа доступа и секретный ключ доступа; адрес службы для всех провайдеров, кроме AWS; при необходимости токен сеанса, бакет по умолчанию и адресация в стиле пути (`path-style`, для MinIO включена по умолчанию) |
| SFTP | Хост, порт (по умолчанию 22), имя пользователя, пароль или закрытый ключ с необязательной парольной фразой, а также отпечаток SHA-256 **`SSH host key fingerprint`** сервера — он обязателен и проверяется при каждом подключении |
| FTP, FTPS | Хост, порт (21 или 990 для неявного FTPS), имя пользователя и пароль; FTPS поддерживает явный режим и **Implicit TLS** и всегда проверяет сертификат сервера по системному хранилищу доверенных сертификатов или по указанному вами **CA Certificate** |

Для FTP, FTPS и SFTP каталоги внутри заданного **Base Path** отображаются как бакеты. SMB не поддерживается.

Gateway хранит секреты, отпечатки ключей хоста и сертификаты CA в зашифрованном виде и никогда не возвращает секреты в форму: пустое поле секрета сохраняет прежнее значение, но при изменении адреса службы, хоста, имени пользователя, протокола или настроек доверия секрет нужно ввести заново. Для раскрытия сохранённых учётных данных нужно право `storage:credentials:reveal`. `storage:credentials:use` позволяет резервному копированию баз данных использовать сохранённые учётные данные без их раскрытия. Бакет, на который ссылаются политики или история резервного копирования, удалить нельзя; для подключений к хранилищам см. [Удаление хранилища, на которое ссылаются резервные копии](#удаление-хранилища-на-которое-ссылаются-резервные-копии).

Вкладка **Objects** позволяет просматривать бакеты и объекты, открывать и редактировать файлы, отправлять файлы, создавать папки и удалять файлы и папки. Пока хранилище отключено, вкладка недоступна. Создание бакета предлагается, когда в подключении нет бакетов, и требует `storage:objects:admin`. Через API можно также удалять бакеты и создавать предварительно подписанные ссылки на скачивание; такие ссылки недоступны для приватного управляемого хранилища, файлы из которого скачиваются через Gateway, а также для FTP, FTPS и SFTP. См. [Права доступа](#права-доступа).

## Управляемое объектное хранилище

Выберите **`Deploy managed storage`**, чтобы развернуть MinIO на ноде хранилища. Среда выполнения — одна проверенная версия MinIO, закреплённая по неизменяемому дайджесту образа; изменить версию на месте нельзя. Перед использованием в рабочей среде изучите порядок её сопровождения и обновления. Ограничения CPU, памяти и диска задаются при создании; Console ограничивает размер диска свободным местом на ноде за вычетом её резерва. Диск — заранее выделенный образ ограниченного размера на ноде хранилища, как у управляемых баз данных. Корневые учётные данные создаёт Gateway; для их раскрытия нужно право `storage:credentials:reveal`.

После создания можно изменить имя, теги, CPU, память, swap, размер диска и публикацию S3. Диск можно только увеличить, а изменение отклоняется, пока ещё применяется предыдущее. Также доступны **Restart** и повтор неудачного создания.

Управляемое хранилище по умолчанию приватно. Gateway обращается к нему через аутентифицированные маршруты Relay, а консоль MinIO никогда не публикуется. Дополнительные пути доступа можно включить явно:

- **`Publish S3 endpoint`** открывает API S3 на порту хоста, по умолчанию 9000. Порт можно изменить после создания.
- **TLS** шифрует S3 сертификатом Gateway Storage CA и включает FTPS.
- **`SFTP access`** и **`FTP access`** открывают службы приёма соединений файловых протоколов на собственных портах, по умолчанию 8022 и 2121; для FTP также нужен диапазон пассивных портов размером до 64 портов. Их можно включить только при создании хранилища; они принимают соединения на всех интерфейсах каждого участника и аутентифицируют клиентов по ключам доступа IAM.

Gateway не изменяет межсетевые экраны хостов. Открывайте только порты, которые нужны определённому клиенту.

### Распределённый кластер

Включите **Distributed cluster**, чтобы запустить MinIO минимум на четырёх нодах хранилища. Каждый участник предоставляет один ограниченный диск, а размер диска определяется самым маленьким участником. Каждому участнику нужен служебный адрес в виде IP-адреса, а не имени хоста, и участники должны быть доступны друг другу по этому адресу; настройте связность участников до создания. В кластере API S3 принимает соединения на служебном IP каждого участника, даже если хранилище не опубликовано, поэтому соответствующим образом ограничьте доступ к этой сети. Создание завершается только после того, как участники сообщат о кворуме чтения и записи. Сейчас адрес подключения Relay для кластера принадлежит основному участнику, поэтому кластер защищает данные на нескольких нодах, но не является отдельной высокодоступной точкой подключения.

### Ключи доступа и привязки рабочих нагрузок

На странице хранилища вкладка **IAM Keys** выдаёт учётные данные S3 с необязательным именем, доступом только для чтения или для чтения и записи, ограничением до 64 бакетов (если бакеты не выбраны — ко всем бакетам) и необязательным сроком действия. Секретный ключ показывается один раз при создании ключа. Для создания и отзыва ключей нужно право `storage:iam`.

**Привязка управляемого хранилища** даёт Container или Deployment приватный доступ к 1–32 бакетам. Добавьте её на вкладке **Environment** рабочей нагрузки; службы Compose не поддерживаются. Gateway выдаёт ключ, ограниченный этими бакетами, запускает для привязки небольшой коннектор в приватной сети и сохраняет значения как управляемые секреты в переменных среды, по умолчанию `S3_ENDPOINT`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `S3_BUCKET` (первый бакет) и `AWS_REGION`. Ключ открывает только перечисленные бакеты, поэтому скомпрометированная рабочая нагрузка не сможет прочитать остальное хранилище. Для создания привязки нужны право `storage:iam` и право изменять переменные среды и секреты рабочей нагрузки.

Для расширенной конфигурации nginx Route может также использовать дополнительную привязку Secure Link к готовому управляемому объектному хранилищу — без общей сети Docker и опубликованного порта S3; клиентам по-прежнему нужны учётные данные S3. Управляемое хранилище не может быть основной целевой службой Route. Для создания привязки нужны право изменять Route и право просматривать хранилище; см. [Приватные целевые службы](/ru/ingress/secure-upstreams/).

Удаление управляемого хранилища стирает его данные на каждом участнике и автоматически удаляет его привязки рабочих нагрузок. Удаление отклоняется, пока на хранилище ссылаются привязки Secure Link из Route, а ссылки из резервного копирования обрабатываются так, как описано ниже.

## Удаление хранилища, на которое ссылаются резервные копии

Политики резервного копирования и активные запуски всегда блокируют удаление подключения к хранилищу или управляемого хранилища: удалите или перенесите политики и дождитесь завершения запусков. Если на хранилище ссылается только завершённая история резервного копирования, удаление отклоняется с кодом `STORAGE_BACKUP_HISTORY_EXISTS` (409), пока вы не подтвердите **Forget history and delete**. Забытая история удаляется из Gateway, поэтому эти резервные копии больше нельзя восстановить или удалить из Gateway, а журнал аудита фиксирует, где находятся их файлы. Файлы подключённого хранилища остаются в его бакетах; файлы в управляемом хранилище стираются вместе с ним.

Через API передайте `backupHistory=forget` в `DELETE /api/object-storage/{id}` или `DELETE /api/managed-storage/{id}`. Инструменты хранилищ в AI Workspace и MCP принимают то же подтверждение в `config.backupHistory`. Чтобы сначала удалить отдельные резервные копии вместе с файлами, используйте [историю резервного копирования](/ru/databases/backups/#правила-удаления-и-хранения).

## Права доступа

| Скоуп | Что разрешает |
| --- | --- |
| `storage:view` | Просмотр подключений, управляемых хранилищ, ключей доступа и привязок |
| `storage:create` | Создание подключений и управляемых хранилищ |
| `storage:edit` | Изменение настроек, перезапуск и повтор создания |
| `storage:delete` | Удаление подключений и управляемых хранилищ |
| `storage:credentials:reveal` | Раскрытие сохранённых учётных данных; включает `storage:credentials:use` |
| `storage:credentials:use` | Использование сохранённых учётных данных резервным копированием баз данных без их раскрытия |
| `storage:iam` | Создание и отзыв ключей доступа и привязок рабочих нагрузок |
| `storage:objects:read` | Просмотр и скачивание объектов и создание предварительно подписанных ссылок на скачивание |
| `storage:objects:write` | Отправка объектов, создание префиксов и удаление объектов |
| `storage:objects:admin` | Создание и удаление бакетов |
| `storage:folders:manage` | Упорядочивание папок хранилищ |

Скоупы можно ограничить одним хранилищем или папкой. См. [справочник скоупов](/ru/identity/scopes-reference/#хранилища).

## Границы эксплуатации

- Для хранилищ нужен тариф Personal или выше; для регистрации ноды хранилища он не нужен. См. [Планы и права по тарифу](/ru/reference/plans-and-entitlements/#матрица-возможностей).
- Ноды хранилища запускают управляемые базы данных, управляемые хранилища и задания резервного копирования; обычные контейнеры приложений и сборки выполняются на нодах Docker и Build Workers. См. [роли нод](/ru/nodes/roles-and-installation/).
- Управляемое хранилище на одной ноде находится на одном хосте. Храните резервные копии и другие важные копии вне его зоны отказа.
- Шифрование, сроки хранения и правила доступа на стороне места назначения настраивайте в той системе хранения, где находятся данные.
